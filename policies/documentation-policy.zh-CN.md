# 文档政策

> 语义源：英文 [Documentation Policy](documentation-policy.md)。本文档为中文对应版本。

## 目的

将文档视为工程资产：足够简洁以便使用，足够具体以指导决策，并在其描述的行为或边界变化时维护。

## 文档所有权

- 将 Toolkit 架构、治理、可复用方法、模板和 Toolkit 维护指引保留在本仓库。
- 将产品愿景、需求、架构、路线图、发布信息和产品特定决策保留在相应产品仓库。
- 将产品 ADR 保留在该产品仓库。Toolkit 仅保留可复用的 ADR 指引和 ADR 模板。
- 当 Toolkit 特定决策影响本仓库的长期结构或治理时，将其保留在 Toolkit 文档中。

## 文档作为变更的一部分

当变更修改公开接口、操作工作流、政策、架构决策、用户或维护者所依赖的行为，或明确记录的契约时，在同一变更中更新相关文档。

不要为重述显而易见的代码或记录短暂的实现细节而创建文档。优先选择简短、持久的说明，而不是穷尽性叙述。

## 契约文档和工作状态

将权威的产品或 Toolkit 文档视为其所在仓库修订的契约。它必须描述已确认且生效的事实、需求、决策、边界和验证预期；不得将待批准事项、进行中的讨论或提议的未来状态表述为当前契约。

将提议工作、未解决问题、迭代进度、临时调查笔记和设备交接状态保留在明确非权威的工作产物中，例如任务列表、迭代文档、Issue 或私有开发状态记录。这些产物可以链接到契约文档，但不得悄然改变它。

必须保留草案时，明确标识其为草案，并确保入口文档和 Agent 路由不会将其视为权威文档。只有在内容已针对相关仓库修订得到确认后，才将草案提升为契约文档。

## 可追溯性和准确性

- 记录后果重大的决策及其背景、所选方向和有意义的权衡。
- 基于可用证据陈述代码、配置、测试、发布状态和执行结果。
- 不得将未经验证的假设、计划操作或推断结果表述为已完成事实。
- 清楚标记示例、草案和已弃用材料，避免 Agent 和维护者将其视为当前政策。

## 维护要求

- 为每份文档赋予一个主要职责，并使用反映其持久目的的名称。
- 对时间顺序属于其身份一部分的记录系列，使用如 `0001-adopt-offline-first-storage.md` 的追加式四位零填充前缀。不得重新编号、复用或重新定义现有标识符。
- 仅当顺序有意义时，对 ADR 和其他决策或记录系列使用有序前缀。不要仅为视觉排序而给普通指南、政策、技能、工作流或模板添加数字前缀。
- 链接到权威的政策、规则、工作流或模板，而不是重复其完整内容。
- 移动、重命名或替换文档时审阅引用。
- 仅在过时材料仍具有决策或迁移价值时保留它；否则移除。归档材料必须标识其替代物，且不应作为活动指引加载。
