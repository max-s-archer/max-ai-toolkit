# 新项目工作流

> 语义源：英文 [New Project Workflow](new-project.md)。本文档为中文对应版本。

## 目的

使用清晰的产品入口、外部 Toolkit 引用、架构和决策记录位置，以及基于证据的构建和验证基线，初始化一个新的产品仓库。

## 输入

- 产品名称、初始问题陈述、目标用户和已授权范围
- 目标仓库位置，以及 Toolkit 定位符或已批准的 Toolkit 修订版本
- 已知的平台、分发、隐私、兼容性和交付约束
- 初始化继续进行前作者必须作出的决策

## 工作流

### 1. 确立仓库边界

将产品仓库创建为独立仓库。保持 Toolkit 为外部依赖；不要将其方法复制到产品仓库中。确认新 Agent 会话必须使用的 Toolkit 定位符。

### 2. 创建产品入口

使用[项目概览模板](../templates/project-overview-template.md)创建产品的公开概览。记录问题、产品目标、当前范围、非目标、平台以及更深入文档的链接。不要编造作者尚未确认的产品事实。

### 3. 创建本地 Agent 路由

依照 [Toolkit 使用模型](../docs/consumption-model.md)创建产品仓库的 `AGENTS.md`。它必须将新会话路由到外部 Toolkit 启动提示词，然后路由到产品自身的文档和项目特定规则。

### 4. 建立架构与决策约定

确定预期的架构文档位置和 ADR 命名约定。在项目入口文档或文档地图中记录这些位置及其创建条件。

只有在已确认系统边界、依赖关系或技术方向时，才创建架构文档。只有在存在后果重大的决定时，才创建 ADR。不得仅为补齐初始仓库结构，而创建空的占位文档、空的决策目录或由模板直接生成的 ADR。

### 5. 建立构建和验证基线

记录构建、测试、lint、静态分析和聚焦手动验证的权威前置条件与命令。对于 Android 项目，在选定实际配置后记录实际 Gradle 任务、受支持的 SDK、设备或模拟器目标，以及已配置的质量工具；不要假定通用 Android 技术栈。

### 6. 规划首个纵向切片

使用[需求分析](../skills/requirements-analysis.md)和[功能开发工作流](feature-development.md)，定义首个小而可观察的产品能力。识别其验收标准、验证方法和文档影响。

### 7. 验证启动准备度

确认新的 Agent 能够解析 Toolkit 定位符、阅读所需入口文档、理解产品边界、运行已记录的验证基线，并识别首个已获授权的任务。

## 完成标准

- 产品具有公开概览，并且本地 `AGENTS.md` 含有明确的 Toolkit 定位符。
- 已记录预期的架构和决策记录位置及其创建条件，且未将尚未作出的决定表述为当前证据。
- 任何初始架构文档或 ADR 都基于已确认的输入或已接受的后果重大决定。
- 构建和验证说明基于实际选择的项目配置。
- 首个纵向切片有明确范围和验收标准。
- 未向 Toolkit 添加任何产品特定事实。
