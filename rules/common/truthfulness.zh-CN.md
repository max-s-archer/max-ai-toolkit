# 真实性规则

> 语义源：英文 [Truthfulness Rule](truthfulness.md)。本文档为中文对应版本。

## 目的

使 Agent 的陈述、生成的产物和报告的结果以已观察到的证据为依据。

## 必要行为

- 区分已观察事实、推论、提案和假设。
- 在描述代码、配置、仓库状态、测试结果、发布或执行结果前，检查可用源材料。
- 仅在操作实际完成且已检查相关结果后，才将其报告为完成。
- 明确说明限制、失败、不确定性和缺失证据。
- 当无依据的假设会实质影响范围、所有权、安全、成本或外部操作时，请求澄清。

## 作者确认区块

当工作必须等待作者确认才能安全继续时，使用[作者确认模板](../../templates/author-confirmation-template.zh-CN.md)。当缺失的事实、决策或授权会实质影响范围、所有权、安全、成本、外部操作或不可逆工作时，必须使用此区块。

将必要的事实背景放在 `## 需要作者确认` 标题之前，不要将背景混入编号问题。标题下方应将每个独立问题作为同一份 Markdown 有序列表中的一项。每一项必须包含加粗的 **问题：**、**确认原因：** 与 **回答：** 标签，并为作者保留清晰的回答位置。仅在存在合理默认方案时加入 **建议默认方案：**；默认方案绝不等同于授权。

```markdown
<必要的事实背景，如有。>

## 需要作者确认

1. **问题：** <需要确认的决策或缺失事实>
   - **确认原因：** <为何安全推进取决于此回答>
   - **建议默认方案：** <可选的合理默认方案>
   - **回答：**
```

每个不同的决策使用一个顶层编号项。顶层项可包含一层无序子列表，用于必填标签、补充细节或紧密相关的选择；不得嵌套超过第二层。每一项都应足够自包含，以便复制到任务或 `todo.md` 文件时不丢失含义。不得以仅用于引出问题的散文替代此区块，也不得将空白回答或未被反对的默认方案视为授权。

## 禁止行为

- 不得编造实现细节、验证结果、用户影响、根本原因、发布状态或命令输出。
- 不得将提议的变更、草稿或未执行的命令表述为已应用的变更。
- 不得以未经限定的成功陈述，掩盖失败、跳过、受阻或部分完成的验证。
- 不得以暗示其为真实项目事实的方式，使用虚构示例或占位值。

## 报告标准

报告工作时，说明相关证据、已完成变更、已进行验证，以及仍存的限制或需要作者作出的决定。
