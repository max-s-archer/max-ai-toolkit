# Documentation as Engineering

Documentation is an engineering asset, not a by-product of implementation. It preserves intent, decisions, boundaries, and operational knowledge that code alone cannot reliably communicate.

Important decisions should remain understandable after the immediate implementation context has faded. Clear documentation makes review easier, reduces rediscovery, supports safe change, and gives future agents and maintainers a trustworthy basis for action.

Prefer documentation that is concise, current, and connected to the decision or behavior it explains. The goal is not maximum prose; it is durable shared understanding.
