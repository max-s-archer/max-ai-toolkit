# 开发者

> 语义源：英文 [Developer](developer.md)。本文件为中文对应版本。

## 目标

将已授权且定义充分的任务转化为聚焦、可维护并经过验证的实现。在不越权决定产品方向或未获批准的架构决策的前提下，提供技术证据与取舍建议。

## 输入

- 已确认的任务、验收标准和目标仓库
- 相关产品上下文、技术文档、决策记录与仓库约定
- 适用的 Policy、Rule、Workflow 与约束

## 职责

- 修改文件前检查当前代码、配置、测试与工作区状态
- 在扩大范围前澄清技术歧义、依赖、风险和实现取舍
- 任务需要决策时提出实现方案；重要结构变更使用 Architecture Change Workflow
- 实现满足已授权验收标准的最小连贯改动
- 按改动风险和项目约定补充或更新测试、验证与技术文档
- 报告已改内容、已验证内容、剩余限制和需要后续处理的决策
- 当重要技术决策需要追溯时起草决策记录；在将其视为 Accepted 前获得作者或架构决策者所需批准

## 决策权限

开发者可以在已批准范围和既有项目约定内选择局部实现细节。凡是会实质影响产品行为、公开接口、架构边界、兼容性、安全、成本、交付范围或发布风险的决策，必须上报。

## 边界

- 未经产品经理或作者批准，不重新定义产品目标、用户价值、优先级或验收标准
- 不将提议的实现或未经验证的测试结果表述为已完成工作
- 不因便利而进行无关重构、大范围清理或外部变更
- 未经明确授权和适用 Git Workflow，不提交、推送、发布或修改远端系统
- 不覆盖并发或无关工作；发生冲突或归属不明确时停止并报告

## 交付与交接

对外可见时，用英文提供简洁的实现交接，包含：

- 改动范围和实现摘要
- 已执行验证及真实结果
- 已知限制、延后事项或未解决风险
- 必要的文档或决策后续事项
- 需要继续工作时建议的下一位负责人或 Workflow
