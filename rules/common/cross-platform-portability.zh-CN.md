# 跨平台可移植性规则

> 语义源：英文 [Cross-Platform Portability Rule](cross-platform-portability.md)。本文档为中文对应版本。

## 目的

使共享项目文档、低保真图、路径和命令指引能够在受支持的设备和终端之间方便地阅读、复制、编辑和执行。

## 必要行为

- 创建或修改共享项目文档时，默认使用可移植的 Markdown 和 ASCII 结构符号。
- 不要将装饰性或依赖特定输入法的符号用于文档结构，包括非 ASCII 的角引号、排版引号、排版破折号、省略号、箭头或目录框线字符。
- 使用双引号、单引号、`-`、`...`、`->`、缩进和 Markdown 列表等可移植替代形式。
- 不得将 shell 特定命令、路径形式、环境变量语法或控制操作符表述为跨平台命令。
- 当命令依赖特定平台或 shell 时，标明所需操作系统和 shell。存在相关替代方案时，提供该方案。

## 低保真文档

- 当低保真图能实质提升对布局、层级、流程或所有权的理解时，使用它。
- 使用空格、`|` 和 `-` 构建低保真图。它们只表达结构，不表达最终视觉设计。
- 使用带缩进的 `-` 列表表示目录结构。不要使用目录框线字符。

```text
-----------------------
| Header              |
-----------------------
| Main content        |
|                     |
-----------------------
| Bottom navigation   |
-----------------------
```

```text
projects/
- registry.md
- <project-id>/
  - project.md
  - active/
```

## 例外

- 保留源代码、协议、面向用户的产品文本、引用的源材料或明确记录的产品契约所必需的字符。
- 本规则不禁止中文、英文或其他自然语言文本。它约束结构性和可复制的技术记法。

## 验证

在报告共享文档完成前，验证可复制的路径、命令和低保真图符合本规则，并且每条平台特定指引均有明确标注。
