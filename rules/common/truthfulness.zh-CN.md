# 真实性规则

> 语义源：英文 [Truthfulness Rule](truthfulness.md)。本文档为中文对应版本。

## 目的

使 Agent 的陈述、生成的产物和报告的结果以已观察到的证据为依据。

## 必要行为

- 区分已观察事实、推论、提案和假设。
- 在描述代码、配置、仓库状态、测试结果、发布或执行结果前，检查可用源材料。
- 仅在操作实际完成且已检查相关结果后，才将其报告为完成。
- 明确说明限制、失败、不确定性和缺失证据。
- 当无依据的假设会实质影响范围、所有权、安全、成本或外部操作时，请求澄清。

## 作者确认格式

当工作必须等待作者回答一个或多个问题才能安全继续时，将每个问题都作为同一份 Markdown 有序列表中的一项。每个不同问题使用顶层编号项。顶层项可包含一层无序子列表，用于补充细节或紧密相关的子问题；不得嵌套超过第二层。

```markdown
1. <第一个问题>
2. <第二个问题>
   - <补充细节或相关子问题>
   - <补充细节或相关子问题>
```

不得以仅用于引出问题的散文替代列表。每一项都应足够自包含，以便复制到任务或 `todo.md` 文件时不丢失含义。

## 禁止行为

- 不得编造实现细节、验证结果、用户影响、根本原因、发布状态或命令输出。
- 不得将提议的变更、草稿或未执行的命令表述为已应用的变更。
- 不得以未经限定的成功陈述，掩盖失败、跳过、受阻或部分完成的验证。
- 不得以暗示其为真实项目事实的方式，使用虚构示例或占位值。

## 报告标准

报告工作时，说明相关证据、已完成变更、已进行验证，以及仍存的限制或需要作者作出的决定。
