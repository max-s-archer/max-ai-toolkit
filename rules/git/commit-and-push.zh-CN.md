# 提交和推送规则

> 语义源：英文 [Commit and Push Rule](commit-and-push.md)。本文档为中文对应版本。

## 目的

仅在变更状态、提交信息、授权和远程目标均已验证后，创建可信的 Git 提交或推送。

## 短触发词

通过[短触发词](../../prompts/short-triggers.zh-CN.md)解析
`提交检查` 和 `提交`。
提交门槛、审阅和授权边界仍以本规则为准。

## 创建提交前

- 确认作者明确授权创建提交。生成信息、检查 diff 或准备文件的请求不构成提交授权。
- 检查当前分支或修订、工作树状态和相关 diff。
- 检查暂存 diff 和暂存文件列表。确认它们只包含预期且已授权的变更。
- 确认暂存变更具有原子性：它只有一个连贯目的，排除了无关清理和临时工作状态，并包含使暂存修订保持内部一致所需的实现、测试和契约文档更新。
- 当暂存权威文档时，验证它描述的是暂存修订引入或保留的已确认状态，而不是待批准、提议或进行中的任务。
- 遇到无关、并发、未跟踪或模糊的变更时停止并报告，而不是默认暂存、丢弃或纳入它们。
- 运行适用验证，并只记录实际完成的检查。
- 当适用 Conventional Commits 时，使用 [Conventional Commit Generator](../../skills/conventional-commit-generator.md) 根据暂存内容生成提交信息。提交前依据暂存 diff 审阅生成的信息；不得提交未经检查或无证据支持的信息。

## 创建和验证提交

- 创建一条与已授权范围一致的原子、连贯且可审查的提交。
- 验证所得提交标识符、主题、变更文件和相关 diff 后再报告成功。
- 准确报告所执行、略过的验证和仍存限制。

## 推送前

- 确认确切的远程、分支或引用以及推送命令。
- 为具体远程写入获得作者明确授权。提交授权不代表推送授权。
- 当另一终端、Agent 或贡献者可能已在提交验证后修改仓库时，重新检查仓库状态。
- 未经明确授权和记录的例外理由，不得强制推送、重写共享历史，或推送机密和无关工作。

## 推送后

- 使用可用证据验证远程结果。
- 报告已推送的引用、提交或标签，以及任何失败或未解决差异。
