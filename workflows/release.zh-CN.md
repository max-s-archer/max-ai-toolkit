# 发布工作流

> 语义源：英文 [Release Workflow](release.md)。本文档为中文对应版本。

## 目的

准备、验证、打标签、编写文档并交接一次发布；不要将 Git 标签或发布平台操作视为发布就绪的替代品。

## 输入

- 已确认的发布版本和预期发布范围
- 目标提交和发布分支
- 项目定义的版本来源、验证要求和发布目的地
- 自上次发布以来的相关变更

## 工作流

### 1. 确立发布意图

确认版本、目标提交、发布分支和发布范围。阅读项目的发布要求和版本来源。若目标、版本或发布授权不明确，停止并请求澄清。

### 2. 准备候选发布版本

确认项目所需的实现、文档、版本元数据和发布资产与预期发布相对应。审阅变更范围和已知未解决限制。

### 3. 验证就绪状态

按发布风险的比例运行项目要求的构建、测试、lint、静态分析和手动验证步骤。准确报告已完成、跳过、失败和不可用的检查。不要将失败或未知的检查变成“可发布”的声明。

### 4. 创建并验证标签

使用[发布标签](../skills/release-tag.md)验证仓库状态、创建带注释的发布标签、生成发布说明、获取远程写入的明确批准，并验证已推送的标签。不要在此重复该技能中的 Git 命令细节。

### 5. 审阅发布说明和平台发布

审阅英文发布说明的准确性、范围、升级影响和已知限制。作者审阅并批准在发布平台上的发布，包括所选标签和上传的资产。

### 6. 记录结果

确认可观察的发布结果：版本、标签、提交、验证摘要、已发布位置（如适用）以及任何后续工作。只记录有证据支持的事实。

## 完成标准

- 发布版本、提交和标签可追溯至相同的发布意图。
- 所需验证结果被准确记录。
- 远程标签创建和平台发布只在获得所需授权后发生。
- 面向发布的文本为英文。
- 未解决限制和后续工作对作者可见。
